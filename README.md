# 梁思钰的生日主页

## 关于这个作品

这是我做完的第一个作品，是为好朋友的生日搭的一页网页。

第一次写，技术上难免粗糙：整页就一个 `index.html`，样式、动画、逻辑全堆在一起，没用框架，也没怎么考虑性能；云端留言、抽卡、烟花这些是想到一处加一处，能跑起来，但离写得漂亮还差得远。

不过它大概会是我改得最久的一个东西。别的练习做完就放着了，这一页还一直挂着，想到什么就添一点，哪里不顺手就改一改；朋友在上面留的话和照片也都还在。技术慢慢补，页面慢慢长。

先记在这儿。

---

一页给思钰的生日礼物。页面本身是单个 `index.html`（双击就能看），照片和留言接了云服务，
需要打开发布后的链接才能同步，详见下面「云服务」一节。

## 里面有什么

- **首屏**：星空、气球、蛋糕，右上角一弯蛾眉月垂着「农历十月初五」的历牌。点「吹蜡烛」火苗会灭、冒烟、撒花、生日歌自动响起来；再点一次重新点燃。气球点一下会炸开，里面藏了一句话。
- **月相 · 农历历牌**：点月亮或牌子会 3D 翻面。正面竖排「十月初五」并标「农历 · 生辰 / 孟冬」，背面是「蛾眉月」「十月 · 小阳春」和两行小字「初五的月亮 / 才弯一道边」；翻面时月亮亮一下、落几颗星，再点翻回来。用鼠标或键盘 Enter / 空格都能翻。
- **卷首 · 关于这一页**：四段「壹 日子 / 贰 这一页 / 叁 不必急 / 肆 收尾」，讲这一页收了些什么。左侧「卷 首」印章点一下会落几颗星并弹一句短句；底部五张卡片可直接跳到各个区块。
- **可点提示**：带 ✦ 角标的地方都能点（气球 / 月相历牌 / 卷首印章 / 签筒 / 记录区照片），悬停或键盘聚焦会说明「点了会怎样」。首次打开首屏会依次自动亮一遍提示；卷首导览标题旁的「✦ 这一页哪里可以点」是一份 10 条清单，点条目直接跳过去。手机上没有悬停，靠常驻角标 + 首次自动提示 + 这份清单。
- **抽一支生日签**（替代原「一封信」）：点签筒或按钮摇一摇，签会飞出来，签纸展开显示签级、今日「宜 / 忌」和一句签文。共 12 支，句句不重样，可以反复摇。
- **100 件小事**：来自之前那份《大学 100 件小事》抽卡器，10 类 × 10 件。抽过的会记住，进度只存在自己浏览器里。点「翻开全部 100 张」能看到 100 张卡片正面，可以搜关键词、按分类筛，点开还能放大。
- **许愿墙**：前 6 颗星是先写好的，自己也能加；新挂的愿望存云端，大家打开链接都能看到。
- **把今天留下来**：左右两栏分开。左边「思钰的这一页」是寿星专属，最上面固定着做网页的人那条预置祝福（金色高亮、末尾带手绘小蛋糕），下面是自己写的感想和照片（点照片能放大）；右边「写给她的话」只放朋友们后来留的祝福。照片和文字存云端，跨设备可见。寿星自己写的每一条也是金色高亮。
- **右下角圆形按钮**：生日歌开关。旋律是用代码合成的，不用额外音频文件。

## 放到 GitHub Pages（拿到一个能点开的链接）

需要一个 GitHub 账号。**本目录已经初始化成 Git 仓库并做过首次提交**，剩下的只有：建仓库 → 跑一次推送 → 网页上开 Pages。

> ⚠️ 接了云服务之后，云端只认 `https://lsy-birthday.app.workbuddy.host` 这个来源。
> 推到 `用户名.github.io` 的那份页面，气球、抽签、烟花照常，但「照片 / 祝福 / 愿望」会提示连不上云端。
> 所以 GitHub 版本适合当静态备份，完整体验请用分享链接。

### 方式 A：一键脚本（最省事）

1. 登录 GitHub，点右上角 **+ → New repository**：
   - Repository name 填 **`你的用户名.github.io`**（必须和账号名一字不差）
   - 选 **Public**
   - **不要**勾 Add a README、不要选 .gitignore / license
   - 点 Create repository
2. 在本目录打开 **Git Bash**（右键 → Git Bash Here），运行：

```bash
bash deploy.sh
```

   按提示输入 GitHub 用户名，回车。第一次推送会弹出 GitHub 登录窗口，登录一次以后就不用再输。
   （脚本提示是英文，避免中文在 Windows 命令行里乱码；内容只是设好 remote 再 push。）
3. 仓库 → **Settings → Pages** → Source 选 `Deploy from a branch`，Branch 选 `main` / `root` → **Save**。
4. 等 1–2 分钟，打开 `https://你的用户名.github.io`。**这个链接就是可以直接发给朋友的地址。**

### 方式 B：不用脚本，手动敲

```bash
git remote add origin https://github.com/你的用户名/你的用户名.github.io.git
git branch -M main
git push -u origin main
```

然后同样去 Settings → Pages 开一下。

> 如果 HTTPS 推送时登录窗口没弹出来，可以在 GitHub → Settings → Developer settings →
> Personal access tokens 生成一个 token（勾 `repo`），推送时把 token 当密码填。

### 方式 C：完全不碰命令行

在新建的仓库里点 **uploading an existing file**，把本目录的 `index.html`、`assets/` 整个文件夹、`README.md` 一起拖进去提交，再按方式 A 第 3 步开 Pages。

> `assets/cards/` 里 102 张 SVG 一定要一起传，否则卡片墙会空。页面写了文字兜底，图丢了不会白屏，但会掉效果。
>
> 不想用 `用户名.github.io` 这个名字也行，普通仓库照样能开 Pages，访问地址变成 `https://用户名.github.io/仓库名/`，页面里都是相对路径，照常能用。

> 本地仓库的首次提交用的是占位作者名 `Birthday Page`，不影响上线。想换成自己的名字，先运行
> `git config user.name "名字"` 和 `git config user.email "邮箱"`，之后的提交就会用新身份。

## 云服务（已开启）

用的是 WorkBuddy 自带的云服务，环境已开通（`billingStatus: normal` / `provisionStatus: assigned`），
不用买服务器、不用配数据库。前端用 CDN 加载官方 SDK，以开通时返回的 `publicConfig` 初始化一次；
代码集中在 `index.html` 的「云服务 · WorkBuddy Cloud Service」这一段。

### 哪些内容在云端

| 内容 | 存在哪 | 谁能看到 |
|------|--------|----------|
| 主人区的照片、感想 | 云数据库 `birthday_posts` | 所有打开分享链接的人 |
| 朋友们的祝福 | 同上 | 同上 |
| 许愿墙新挂的愿望 | 同上 | 同上 |
| 前 6 颗预置愿望、置顶那条祝福 | 写在 `index.html` 里 | 所有人（不进数据库） |
| 100 件小事的抽卡进度 | 浏览器本地 | 只有自己这台设备（个人浏览状态，没必要共享） |

数据表 `birthday_posts` 字段：`client_key`（去重、判断是哪台设备写的）、`kind`（post / wish）、
`side`（owner / friend / wall）、`role`、`author`、`body`、`photo`（压缩后的图片）、`created_at`。
已开启行级安全（RLS），访客可读 / 可写 / 可删；写入有长度限制（正文 500 字、署名 40 字、图片 40 万字符内）。

照片在上传前压到最长边 **800px**，作为内嵌数据存进数据库。这样做是因为云文件存储模块要求先登录，
而这是发给朋友的生日页，不希望访客先注册才能传照片。

### 要紧的取舍

- **没有登录**：访客打开就能写祝福。代价是这属于公开留言板——拿到链接的人都能看到、也能删除留言；
  页面上只给「本机自己写的」显示 × 按钮，这只是界面限制，不是权限隔离。以后在意的话可以加登录模块，
  把表改成按用户归属隔离。
- **认域名**：云端校验访问来源，只允许 `https://lsy-birthday.app.workbuddy.host`。
  双击本地文件、或放到 GitHub Pages 时，记录区会提示「云端连不上」，其余功能不受影响。
- **旧数据自动迁移**：第一次用分享链接打开时，把这台设备以前存的本地记录 / 愿望搬到云端
  （按 `client_key` 去重，只做一次），原始数据仍留在浏览器里、不会被删。
- **失败不静默**：断网、额度用完、权限不足都会给一句明确提示，不会假装保存成功。

本次开通没有付款步骤，当前在体验版免费额度内。按[官方定价页](https://www.workbuddy.cn/docs/workbuddy/Pricing)

|------|------|----------|--------------------|-------------------|
| 体验版 | 免费 | — | 10 个 | 5,000 |
| 标准版 | 99 元 | 70 元 | 30 个 | 25,000 |
| 高级版 | 199 元 | 140 元 | 50 个 | 50,000 |
| 旗舰版 | 999 元 | 700 元 | 99 个 | 150,000 |

**什么时候才会花钱**：不会自动扣费。开通、发布、日常写留言都在体验版免费额度内；
只有两种情况需要主动付钱——想把额度撑大而升级会员，或同时开云服务的应用超过 10 个要加名额。

- **按量消耗**：数据库 CPU / 容量、服务调用次数、访问频率超额、文件读写都算资源点。
  这一页只用了数据库（照片压成 800px 内嵌进数据表，不占文件存储），没开登录、没用短信；
  消耗主要看**打开链接的人次**和**攒下来的照片 / 留言条数**——每次打开会读一遍全部记录。
- **按月刷新**：从本应用开启云服务当天起算，每月自动刷新，未用完的额度不累积；用量每小时更新，有延迟。
- **用尽不会扣钱，会暂停**：资源点耗尽时云服务自动暂停，暂停期间不消耗，页面其余部分照常能看，
  但留言 / 照片 / 愿望会连不上。可以等下次刷新自动恢复，或升级会员提前恢复
  （中途升级只提高上限，已用掉的不清零，刷新日不变；同档续费不补当前周期）。
- **⚠️ 暂停有期限**：数据从暂停当天起保留 **30 天**（旗舰版 60 天），期间**不能访问也不能导出**；
  到期仍未恢复，云端数据会被永久删除，应用本身还在。所以要在服务正常时定期导出 CSV 备份。
- **看用量**：「设置 → 数据管理 → 应用」→ 点这个应用的云服务图标；或在应用预览里点标题旁「云服务」。
  能看到已用资源点、各项消耗明细、距下次刷新的天数。

> AI 对话消耗的「积分」和云服务的「资源点」是两套独立额度；加量包买的是积分，补不了资源点。
> 纯展示、不开云服务的应用既不消耗资源点，也不占应用名额。

## 日常维护

### 两条链接，别发错

| 链接 | 用途 | 云端功能 |
|------|------|----------|
| `https://lsy-birthday.app.workbuddy.host/?sharecode=…` | **发给朋友的主链接**（完整链接见发布卡片，单独发） | 正常 |
| `https://你的用户名.github.io` | GitHub Pages 静态备份 / 作品展示 | 连不上（云端只认前一个域名） |

`?sharecode=...` 相当于访问凭证，转发范围＝能看到留言和照片的范围。
**别把带 sharecode 的完整链接写进公开仓库或 README**：这份文件会推到公开 GitHub，
谁看到仓库谁就能打开记录区、也能删留言。要给朋友就单独发完整链接。

### 改一次东西的完整流程

1. 改 `index.html` → 双击本地预览（Ctrl + F5 强刷），云端功能会显示离线，属正常。
2. 说一声「更新线上」重新发布，链接不变；改的是线上快照，云端里已有的留言和照片不受影响。
3. 线上确认无误后 `git add -A` → `git commit -m "改了什么"` → `git push`，让 GitHub 那份备份也跟上。
4. 改坏了用 `git checkout -- index.html` 回滚；发布目录外的五个备份目录不会被打包上线。

只改本地文件、不重新发布，朋友点链接看到的还是旧版。

### 数据维护

- **预览版和已发布版共用同一个云服务**：在预览里试写的祝福 / 传的照片会进正式数据，测完记得在页面上点 × 删掉。
- **定期备份**：云服务管理页 →「数据库 → 数据」→ 选 `birthday_posts` →「导出 CSV」。要在服务正常时导，暂停期间导不了。
- **公开留言板**：拿到链接的人都能读、能写、能删；页面只对「本机写过的」显示 ×，这不是权限隔离。
  真要收紧可以加登录模块，把表改成按用户归属隔离（见上面「要紧的取舍」）。
- **下线 ≠ 删除**：下线应用不会删云端数据；**删除应用会永久删掉数据、文件和注册用户，且无法恢复**，
  即便之后用源码重建也找不回来。目前也不支持单独关闭云服务来腾名额。

### 长期迭代

- 每年复用要改：年份 `2026`、农历历牌（`<b class="lt-date">`）、卷首 / 签文里带年份的句子。
- 100 件小事的抽卡进度存在各自浏览器本地（`localStorage`），不进云端、换设备不继承，也不用备份。
- 想加「只有寿星能写」的门槛，填 `OWNER_CODE`；想给置顶祝福加暗号，填 `SPECIAL_CODE`（默认留空＝不设）。
